# Public portfolio publication checklist

Run this before changing any project to `published: true`.

## Confidentiality

- [ ] No unreleased product capabilities.
- [ ] No internal Jira/ticket screenshots.
- [ ] No private Figma links or unapproved Figma screenshots.
- [ ] No Slack/internal discussion screenshots unless explicitly approved and sanitized.
- [ ] No internal roadmap information.
- [ ] No security-sensitive implementation details.
- [ ] No customer information or names unless already public and appropriate to reuse.
- [ ] No internal metrics or business data without permission.
- [ ] No employee personal information.
- [ ] Every IBM visual is either publicly released, explicitly approved, or recreated/sanitized.

## Accuracy

- [ ] Role verbs accurately distinguish owned / led / proposed / influenced / partnered / reviewed / supported.
- [ ] Team members/disciplines are described accurately.
- [ ] Outcome claims have evidence.
- [ ] No fabricated metrics.
- [ ] Dates and release status are correct.

## Hiring-manager value

- [ ] The problem is understandable quickly.
- [ ] Why the problem mattered is clear.
- [ ] Madhav's specific contribution is obvious.
- [ ] At least one meaningful decision and its reasoning is visible.
- [ ] Collaboration is specific rather than generic.
- [ ] The final solution is visible or clearly described.
- [ ] The project proves a capability not already overrepresented elsewhere.

## Accessibility / quality

- [ ] Heading hierarchy is logical.
- [ ] Images have appropriate alt text.
- [ ] Color contrast is sufficient.
- [ ] Links are descriptive.
- [ ] Mobile layout is checked.
- [ ] Keyboard navigation works.
- [ ] Reduced motion is respected.
- [ ] Spelling and grammar are checked.
